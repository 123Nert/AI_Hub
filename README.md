# AI 情报站

一个运行在本机的 AI 资讯聚合页。把中文/英文官方机构、科技媒体、微信公众号和博主内容汇集在一个可搜索、可筛选的页面里。项目不依赖第三方 npm 包，仅使用 Node.js 内置模块。

## 功能

- 汇总公开 RSS / Atom 资讯源、微信公众号桥接源、B站 UP 主视频和搜狐号同步文章。
- 按 **官方机构 / 官方媒体 / 社区 / 博主·UP主 / 论文 / 新仓库** 及 **中文 / English** 及**具体来源**筛选，可交叉组合。
- 按标题和摘要搜索，提供最近 24 小时、工具/教程/工作流、模型/发布/评测、📱手机上新、⭐收藏快捷筛选。
- **阅读追踪**：点击卡片自动标记已读（淡化显示），上次访问之后的内容带 NEW 角标，可一键"全部已读"。
- **收藏**：卡片右上角星标收藏，收藏内容可在快捷视图中单独查看。
- **主题订阅页**：预设 Agent / 生成式 / 大模型 / 具身智能 / 产品工具五个主题，按关键词正则聚合不同来源的内容；支持自定义主题（名称 + 正则），保存在本机。
- **关键词屏蔽**：按正则规则隐藏不感兴趣的标题/摘要（如招聘、软文），启用开关与规则保存在本机，状态栏显示屏蔽计数。
- **7 日热词**：按标题分词统计近 7 天高频词，点击热词即按该词搜索。
- **每日简报**：页头「📰 简报」打开 `/digest`，服务端把最近 24 小时内容按类型分组并附热词，浅色排版、可直接打印或存 PDF。
- **导出**：一键把当前筛选结果导出为 Markdown 或 JSON 文件。
- **深浅色主题**：跟随系统自动切换，也可手动固定浅色/深色。
- **源健康看板**：页头「📊 源状态」以红黄绿状态列出每个源的条目数、最近成功时间、失败原因与连续失败次数。
- **跨源同题聚合**：不同来源报道同一事件时自动合并为一张卡片，标注「另有 N 条相同报道」，可展开查看各来源链接（判定：标题归一化后一致或高度相似，且发布时间相差不超过 72 小时）。
- **抓取健壮性**：每源失败自动重试（指数退避）并有全局并发上限；某源抓取失败时保留上一轮内容、只标错误不丢数据；支持 ETag / Last-Modified 条件请求，源未更新时直接复用本地数据。
- **源状态统计**：`/api/stats` 接口返回每个源的最近成功时间、条目数、连续失败次数与最近失败原因；控制台输出结构化 JSON 日志。
- **分页加载**：每页 60 条 + 加载更多，全部内容可完整浏览。
- **卡片缩略图**：自动提取条目配图（RSS enclosure / media 标签 / 正文首图 / B站封面），无图卡片不受影响。
- 点击卡片打开原始文章或视频。
- 15 分钟本地缓存；缓存过期时先显示旧内容，再后台更新；服务端每 10 分钟主动自检刷新，打开页面即是热缓存。

已读、收藏、筛选偏好保存在浏览器 localStorage（本机），上限 3000 条按时间淘汰，不同浏览器之间不共享。

## 信息源

来源在 `server.js` 顶部的 `SOURCES` 数组定义。大致包括：

- **官方机构**：OpenAI、Google AI、Hugging Face、NVIDIA Generative AI、Google DeepMind。
- **官方媒体**：量子位、机器之心、新智元、爱范儿、IT之家、少数派、Hacker News、TechCrunch AI、The Verge AI、极客公园。
- **博主 / UP主**：夕小瑶科技说、APPSO、歸藏的 AI 工具箱、AI进化论·花生、老石谈芯、Simon Willison。
- **论文**：arXiv cs.AI 与 cs.CL（官方 API，按提交时间倒序取最新 30 篇）。
- **社区与仓库**：Reddit r/LocalLLaMA（Atom 源）、GitHub 热门新仓库（官方 Search API，近 7 天按 topic 分查合并取星数最高）。
- **手机垂媒**：MacRumors（苹果）、9to5Google（Pixel/安卓）、Android Authority（安卓生态）；配合「📱 手机上新」快捷栏目看各品牌新机动态，简报页也有对应板块。

微信公众号通过第三方 [wechat2rss](https://wechat2rss.xlab.app/) 服务同步，不是微信官方 API；B站列表通过公开页面接口读取，可能受平台风控、网络环境和接口变更影响。源抓取失败时，页面会标明失败源，其余内容仍可使用。

## Windows 快速开始

1. 安装 [Node.js](https://nodejs.org/)（建议 LTS，Node.js 18 或更新版本）。
2. 解压/克隆整个项目文件夹；不要只复制 `index.html`。
3. 双击 `launch.vbs`。脚本会尝试从 PATH 和常见安装目录查找 Node.js、启动本地服务并打开主页。

服务启动后也可直接访问：<http://127.0.0.1:8437/>。仅用于检查服务健康状态的接口是 <http://127.0.0.1:8437/api/ping>，会返回 `pong`，不是主页。排查抓取状态可用 <http://127.0.0.1:8437/api/stats>，返回每个源的最近成功时间、条目数、连续失败次数与失败原因。

### 命令行启动

在项目文件夹运行：

```powershell
node server.js
```

然后浏览器打开 <http://127.0.0.1:8437/>。默认端口被占用时，服务会顺延尝试 8438–8441，并将实际端口写入本地 `port.txt`。

## 添加或移除来源

在 `server.js` 的 `SOURCES` 数组增删一项：

```js
{ key: "example", name: "Example AI", kind: "rss", type: "institution", lang: "en", url: "https://example.com/feed.xml" }
```

字段说明：

- `key`：唯一标识，应与其他来源不同。
- `name`：页面上显示的来源名称。
- `kind`：`rss`、`bilibili`、`sohu` 或 `gh`（GitHub Search API）。
- `type`：`institution`、`media`、`community`、`blogger`、`paper` 或 `repo`。
- `lang`：`cn` 或 `en`。
- RSS 源提供 `url`；B站来源提供 UP 主 `mid`；搜狐号来源提供 `authorId`。

修改来源后停止并重新启动 `node server.js`。若需要立即清除旧抓取结果，可先停止服务，再删除本地 `aihub-cache.json`；服务会重新抓取并生成缓存。

## 隐私与网络说明

- 服务仅监听 `127.0.0.1`，不会作为局域网或公网服务器对外开放。
- 读取公开信息源并在本地生成 `aihub-cache.json`；缓存、端口、Node.js 路径等运行状态文件默认不纳入 Git。
- B站抓取会携带其公开接口需要的匿名访客标识 cookie；不使用账号登录凭据。
- 所需网络访问依赖各内容站点与桥接服务的可用性；个别源临时失败不影响其他来源。
